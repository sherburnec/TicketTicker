# Adding a city

A city is a folder, `data/<city-id>/`. Add the folder and rebuild; no code changes (FR-13, NFR-7). The city selector lists every folder that has a `city.json`.

| File | Purpose |
|---|---|
| `city.json` | `city_id` (must equal the folder name), `name`, `time_zone`, `payment_window_days`, `extent` (`bbox` or `polygon`), `exclusion_zones`, `depot`, optional `hot_zone_weights` |
| `segments.geojson` | Street segments. `segment_id` is `<city-id>-<osm node>-<osm node>`. Generated by `scripts/build-segments.ts` |
| `blocks.csv` | Block numbers and address ranges per segment. Generated by `scripts/build-blocks.ts` |
| `fine-schedule.csv` | The city's own fine schedule (below) |
| `named-locations.csv` | One row per address of each named location. `named-locations.template.csv` shows the columns and is never read |

## The fine schedule

The schedule belongs to the city. It can hold any number of rows, and the codes are written however the city writes them (`CVC-22500(g)`, `BMC 6-1-1101`, `MMC 10.04.010`). Nothing outside this file names a citation code.

Columns, in any order; extra columns are ignored:

| Column | Required | Meaning |
|---|---|---|
| `citation_code` | yes | The key matched against the citation file's `Citation code` |
| `citation_name` | yes | Shown in reports |
| `base_amount` | yes | Fine before escalation |
| `escalated_amount` | yes | Fine after the payment window |
| `start_date` | no | ISO date the row takes effect. Use it for fine increases |
| `escalation_days` | no | Overrides the city's `payment_window_days` for this code |
| `sample_weight` | no | Relative share of this code in generated sample data (default 1) |

Rules:
- A code may repeat, but only one row per code may have a blank `start_date`, and no two rows may share a start date. A citation uses the row with the latest `start_date` on or before its date; a blank start date counts as the beginning of time.
- The code source (used by the code-source filter) is the text before the first `-` or space: `BMC 6-1-1101` and `BMC-ART30` are both `BMC`.
- Amounts that are estimates must be labelled as such in the city's `SOURCES.md` until replaced (DR-8, OQ13).
- A bad file fails with an error naming the file and line.
